# 念匣 · NianBox

**Capture first, organize later.** A minimal native macOS memory inbox with a self-hosted server. Capture with the corner panel or `Control–Option–Space`; access the same tasks from Hermes through the independent `nianbox` MCP service.

Based on [Peekaboo](https://github.com/Emanuele-web04/Peekaboo) by Emanuele Di Pietro. The original MIT license and copyright are retained. This fork is for personal, non-commercial, self-hosted use and remains MIT-licensed.

- macOS 14+, SwiftUI, menu bar, corner hover, global shortcut, quick capture and priorities.
- SQLite + FastAPI REST + authenticated Streamable HTTP MCP, independent of the Mac app.
- Completed tasks remain until explicitly deleted. No mobile app or paid Apple service is required.
- macOS sync and Hermes verification status: [verification](docs/verification.md).

## Install the Mac app

Download the Universal DMG from [GitHub Releases](https://github.com/takboo/nianbox/releases/latest), open it and drag NianBox to Applications. Open NianBox from Applications; use the menu bar, corner or global capture shortcut. Configure your preferred shortcut in Settings; Escape cancels recording, Delete disables it, and Restore default resets it to Control–Option–Space. You can begin offline and connect a server later.

Personal builds are ad-hoc signed and not Apple-notarized. On first download macOS may require an explicit Privacy & Security → Open Anyway decision; no system security settings need to be disabled.

## Build the Mac app

Requires Xcode 16+ (verified with Xcode 26.2). Open `NianBox.xcodeproj`, choose `NianBox` and run. Ad-hoc signing is configured; no developer team is required.

```sh
xcodebuild test -project NianBox.xcodeproj -scheme NianBox \
  -destination 'platform=macOS' -only-testing:NianBoxTests
```

The generator requires Ruby 3.2+ and Bundler 4. The checked-in project is generated by `Scripts/generate_project.rb`. Install Ruby dependencies with `bundle install`; regenerate with `bundle exec ruby Scripts/generate_project.rb`; verify with `bundle exec ruby Scripts/verify_project_generation.rb`. Only the Mac app and its two test targets are generated.

## Run NianBox Server

```sh
cp .env.example .env
# Set NIANBOX_API_TOKEN in .env to a generated secret (at least 32 characters).
docker compose pull
docker compose up -d --no-build
```

Prebuilt Linux AMD64/ARM64 images come from `ghcr.io/takboo/nianbox`; pin the published digest for reproducible deployments. To build local source, use `docker compose -f compose.yaml -f compose.build.yaml up -d --build`. The default port binds to `127.0.0.1:8088`. Data lives in the named `nianbox-data` volume. HTTPS/private-network deployment, image updates, backups and recovery: [deployment](docs/deployment.md). Hermes configuration: [Hermes](docs/hermes.md). Protocol and conflict rules: [sync](docs/sync.md).

For development:

```sh
cd Server
uv sync --locked
# Set NIANBOX_API_TOKEN and NIANBOX_DB outside the repository's tracked files.
uv run uvicorn nianbox.app:create_app --factory --host 127.0.0.1 --port 8088 --no-access-log
uv run pytest -q
```

MCP endpoint: `/mcp/`; tools: `list_tasks`, `get_task`, `create_task`, `update_task`, `complete_task`, `delete_task`. REST: `/v1/tasks`, `/v1/mutations`, `/v1/changes`, `/v1/export`. All require `Authorization: Bearer <token>`; only the minimal `/health` endpoint is anonymous.

Statuses reuse upstream semantics: `todo`, `inProgress`, `done`, `backlog`. Priorities: `none`, `low`, `medium`, `high`. Only title is required. Dates use RFC 3339 with an explicit timezone. Hermes interprets natural language; the server stores structured fields.

## Upstream maintenance

The repository retains upstream Git history and an `upstream` remote. Fetch upstream and selectively review/cherry-pick Mac interaction fixes. This fork intentionally replaces the old iOS/CloudKit contract; merging upstream's project generator wholesale can restore removed targets. Run generation verification before accepting updates. No automatic import or modification of old Peekaboo stores occurs.

See [LICENSE](LICENSE).

Interactive UI tests operate the real mouse/keyboard and can show macOS permission dialogs. Use the [isolated macOS VM workflow](docs/macos-vm-testing.md) by default. Unattended checks use server tests, Mac unit tests and `Scripts/verify_sync.sh`; see the current [verification record](docs/verification.md) for pending UI/live acceptance.
